# Roomly

Roomly — внутренний учебный сервис Northstar Labs для поиска и бронирования переговорных. Сотрудник может найти комнату, создать, изменить и отменить собственную будущую встречу; администратор дополнительно управляет каталогом комнат и отменяет будущие встречи других сотрудников с обязательной причиной.

Полное наблюдаемое поведение первого релиза определено в [функциональных требованиях](docs/requirements.md). План реализации и статус работ находятся в [плане](docs/implementation-plan.md). Правила выбора селекторов для автоматизации описаны в [руководстве по автоматизации](docs/test-automation.md).

## Требования к окружению

- Node.js 24 LTS (проверьте `node --version`; версия зафиксирована в `.nvmrc`).
- npm 11 или новее.
- macOS или Linux. На Windows проект в первом релизе не поддерживается и не проверяется.
- Chromium для Playwright smoke-проверок. Если браузер не установлен, установите его обычной командой Playwright для текущего окружения.

Docker не требуется и в первом релизе не поддерживается. Приложению не нужны внешние сервисы: база данных SQLite и изображения комнат хранятся локально.

## Быстрый старт

Из корня репозитория:

```bash
npm ci
npm run setup
npm run dev
```

`npm ci` устанавливает ровно версии из `package-lock.json`. `npm run setup` применяет миграции и заполняет локальную базу начальными данными. `npm run dev` запускает backend и frontend одновременно; остановите оба процесса сочетанием `Ctrl+C`.

Адреса при запуске в development-режиме:

| Что | Адрес |
| --- | --- |
| SPA | http://localhost:5173 |
| API | http://localhost:3000/api/v1 |
| Health check | http://localhost:3000/api/v1/health |
| Swagger UI | http://localhost:3000/api/docs |
| OpenAPI JSON | http://localhost:3000/api/openapi.json |

Локальная development-база создаётся в `data/roomly.sqlite`; этот каталог намеренно не добавляется в Git.

### Production-сборка

```bash
npm run build
npm run start
```

После сборки один процесс на `http://localhost:3000` обслуживает и SPA, и API. В этом режиме Swagger и OpenAPI JSON доступны по адресам `/api/docs` и `/api/openapi.json` на том же origin.

## Исходные данные локального стенда

`npm run setup` и `npm run db:reset` создают следующие учётные записи. Это публичные пароли **только для локального учебного стенда** — не используйте их в других системах.

| Роль | Email | Пароль |
| --- | --- | --- |
| Сотрудник | `employee@northstar.local` | `EmployeePass!2026` |
| Сотрудник | `employee2@northstar.local` | `EmployeePass!2026` |
| Администратор | `admin@northstar.local` | `AdminPass!2026` |

Seed также создаёт три комнаты (`Атлас`, `Борей`, `Кедр`) и показательные будущую, идущую, завершённую и отменённую встречи. Времена привязаны к текущему моменту выполнения seed, поэтому даты встреч намеренно меняются после сброса базы.

### Сброс базы

```bash
npm run db:reset
```

Команда удаляет **только** локальную development-базу `data/roomly.sqlite` и её SQLite sidecar-файлы, затем заново применяет миграции и seed. Она откажется от работы в production-окружении или с иным путём к базе. Все созданные локально комнаты, бронирования и сессии будут безвозвратно заменены исходными данными.

## Проверки

Все команды выполняются из корня репозитория.

| Назначение | Команда |
| --- | --- |
| Линтер | `npm run lint` |
| Проверка типов | `npm run typecheck` |
| Unit и component tests | `npm run test:unit` |
| API integration tests | `npm run test:integration` |
| Все unit/component/integration tests | `npm run test` |
| Полный набор lint + types + tests | `npm run check` |
| Playwright smoke e2e на исходных данных | `npm run test:smoke` |

`npm run test:smoke` сначала выполняет `db:reset`, затем запускает smoke-сценарии входа, создания, изменения и отмены своей встречи, а также административного создания комнаты и отмены чужой встречи. Повторный запуск не требует ручной очистки данных.

## Границы первого релиза

Roomly обслуживает один офис и один московский часовой пояс. В первом релизе намеренно отсутствуют регистрация и управление пользователями или паролями, многодневные и повторяющиеся встречи, уведомления, внешние календарные интеграции, отчёты, бронирование рабочих мест, восстановление отменённых записей и окончательное удаление комнат или бронирований. Полный список ограничений приведён в [разделе 25 требований](docs/requirements.md#25-ограничения-первого-релиза).

## Допустимые ограничения

- Поддерживаются только macOS и Linux; Windows не входит в область поддержки первого релиза.
- Проект предназначен для локального учебного стенда и не включает развёртывание, Docker-конфигурацию или внешние обязательные сервисы.
- Сессия действует восемь часов без продления; это правило задано требованиями, а не является механизмом долговременного входа.
