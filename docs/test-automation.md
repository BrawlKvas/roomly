# Правила автоматизации Roomly

Сначала выбирайте элементы по семантике: роли, accessible name и связанным `label`. Это делает тесты похожими на реальное использование интерфейса и сохраняет их понятными.

`data-testid` разрешён только когда семантический селектор неоднозначен: для повторяющихся записей каталога и списков. Имена пишутся в kebab-case и отражают стабильную сущность, например `room-card-{roomId}` и `booking-row-{bookingId}`. В качестве суффикса используется постоянный идентификатор уже сохранённой записи, никогда не отображаемый текст, индекс, текущая дата, случайное значение или CSS-класс.

Диалоги выбираются по роли `dialog` и заголовку. Формы, поля и кнопки выбираются по label и accessible name. Ошибки должны иметь роль `alert`; при серверской ошибке фокус переносится на сообщение, а при закрытии диалога Material UI возвращает его на кнопку, открывшую диалог.
