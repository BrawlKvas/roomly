# Roomly: руководство для тестировщика

## Что такое Roomly

Roomly — внутренний сервис Northstar Labs для поиска и бронирования переговорных в одном офисе. Сотрудник ищет свободную комнату, создаёт, изменяет и отменяет свои будущие встречи. Администратор обладает теми же возможностями и дополнительно управляет каталогом комнат и отменяет будущие встречи других пользователей с указанием причины.

Стенд предназначен для практики исследовательского, UI E2E- и API-тестирования. В нём можно отрабатывать чтение требований, анализ ролей и прав доступа, работу с REST API и Swagger, проектирование проверок, UI-селекторы, негативные случаи, границы и конкурентные запросы. Это не набор намеренно сломанных примеров: найденные дефекты следует оформлять на основании требований.

## Что потребуется

- Node.js 24 LTS и npm 11 или новее (`node --version`, `npm --version`);
- macOS или Linux;
- Chromium для запуска browser smoke-проверок. Если Playwright сообщает об отсутствии браузера, из корня репозитория выполните `npx playwright install chromium`.

Docker, учётные записи внешних сервисов и сетевые зависимости не нужны. Локальная база — SQLite, изображения комнат также хранятся локально.

## Установка и запуск

Все команды выполняйте из корня репозитория.

```bash
npm ci
npm run setup
npm run dev
```

`npm ci` устанавливает версии из lock-файла. `npm run setup` применяет миграции и добавляет исходные данные. `npm run dev` запускает API и SPA одновременно; для остановки нажмите `Ctrl+C`.

В development-режиме доступны:

| Ресурс | Адрес |
| --- | --- |
| SPA | http://localhost:5173 |
| REST API | http://localhost:3000/api/v1 |
| Health check | http://localhost:3000/api/v1/health |
| Swagger UI | http://localhost:3000/api/docs |
| OpenAPI JSON | http://localhost:3000/api/openapi.json |

Swagger — удобная точка входа для ручных API-проверок. Авторизация использует cookie: сначала выполните вход через `POST /api/v1/auth/login`, после чего используйте операции в той же браузерной сессии Swagger.

Для проверки production-сборки используйте:

```bash
npm run build
npm run start
```

После этого один процесс обслуживает SPA на `http://localhost:3000`, API по `http://localhost:3000/api/v1`, Swagger по `http://localhost:3000/api/docs` и OpenAPI JSON по `http://localhost:3000/api/openapi.json`.

## Учётные записи и исходные данные

Пароли ниже публичны только для локального учебного стенда. Не используйте их в других системах.

| Роль | Email | Пароль |
| --- | --- | --- |
| Сотрудник | `employee@northstar.local` | `EmployeePass!2026` |
| Администратор | `admin@northstar.local` | `AdminPass!2026` |

Seed создаёт комнаты «Атлас», «Борей» и «Кедр», а также показательные будущую, идущую, завершённую и отменённую встречи. Время seed вычисляет относительно момента запуска, поэтому календарные даты не фиксированы и меняются после сброса. Для новых проверок выбирайте рабочий день и свободный будущий интервал.

Все даты и часы относятся к часовому поясу офиса: Москва, UTC+03:00 без сезонного перевода. Время устройства не меняет правила Roomly. Полные правила времени, доступности и конфликтов находятся в [требованиях](requirements.md).

## Сброс и восстановление стенда

Чтобы удалить эксперименты и вернуть известное начальное состояние, выполните:

```bash
npm run db:reset
```

Команда удаляет только `data/roomly.sqlite` и его SQLite sidecar-файлы, заново применяет миграции и seed. Она защищена от удаления произвольной или production-базы. Все локально созданные комнаты, бронирования и сессии при этом будут потеряны.

Если запуск был прерван, остановите процессы и снова выполните `npm run db:reset`, затем `npm run dev`. Если проблема связана с зависимостями, повторите `npm ci`; если с browser-проверками — установите Chromium указанной выше командой.

## Команды проверки

| Назначение | Команда |
| --- | --- |
| Линтер | `npm run lint` |
| Проверка типов | `npm run typecheck` |
| Unit и component tests | `npm run test:unit` |
| API integration tests | `npm run test:integration` |
| Все unit/component/integration tests | `npm run test` |
| Полный набор lint + types + tests | `npm run check` |
| Browser smoke на чистых данных | `npm run test:smoke` |

Smoke-проверки — короткий контроль исправности стенда, а не готовое покрытие для обучения. Перед запуском они сами выполняют `db:reset`; повторять их можно без ручной очистки данных.

## Документация и селекторы

- [Функциональные требования](requirements.md) — основной источник ожидаемого поведения. При конфликте с кодом, планом или другим документом приоритет у требований.
- [Упражнения](exercises.md) — темы практики в рекомендуемом порядке; это не решения.
- [План реализации](implementation-plan.md) — история и контрольные точки реализации, но не альтернативная спецификация.
- [Правила автоматизации](test-automation.md) — UI-элементы сначала выбираются по роли, accessible name и связанному label. Точечный `data-testid` предназначен для повторяющихся карточек и строк; его суффикс содержит постоянный ID сущности, а не текст, индекс или дату.

Ошибки API возвращаются в стабильном JSON-конверте с полями `status`, `code`, `message`, `fieldErrors` и `requestId`. Для своих проверок опирайтесь прежде всего на HTTP-статус и `code`, а `requestId` сохраняйте в отчёте для диагностики.

## Ограничения первого релиза

Стенд обслуживает один офис и один часовой пояс. В нём нет регистрации, управления пользователями, ролями или паролями, многодневных и повторяющихся встреч, уведомлений, внешних календарей, отчётов, бронирования рабочих мест, восстановления отменённых записей и окончательного удаления комнат или бронирований. Поддерживаются только macOS и Linux; Docker и развёртывание в первом релизе не предусмотрены. Полный перечень — в [разделе 25 требований](requirements.md#25-ограничения-первого-релиза).
